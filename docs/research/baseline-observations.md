# RED 基线观察

## 方法与判定边界

2026-10-07，在新 Skill 入口和安装文件均不存在时，四个 `fork_turns="none"` 独立上下文各收到一个场景的原始请求。预期和失败信号由观察端维护，没有交给采样端。完整最终回答与一次编排澄清见 [原始记录](../../tests/results/baseline.md)。默认已有技能仍可被调用；这是新 Skill 的增量基线，不是移除所有技能的纯模型测试。

本轮仅评估首次回应和策划决策。封面、截图等实际附件未发送，不能据此判断真实成品质量、图像生成能力、中文错字或最终发布核验失败。输出中未声明的流程属于“方案遗漏”，与直接违反原则区分。没有收到明确的自我合理化陈述，以下引文均为实际回答，不补造失败原话。

判定依据为已批准的 [设计规范](../superpowers/specs/2026-10-07-education-ecommerce-designer-skill-design.md)，尤其是单变量 A/B、不得使用教育保证性承诺、权利门槛与交付包标准。本观察不另行作法律结论，后续正式生产必须依据当前官方来源核验。

## 最小范围与保留的正确行为

本轮发现真实缺口，未触发“四个场景全部自然满足要求则停止新增冗余规则”的条件。最明确的增量是单变量 A/B 检查和保证性文案分类。生产方案的购买信息槽位、素材授权字段及交付结构也有观察支持，但只能称首次策划中的遗漏，不能声称代理在最终生产时必然不执行检查。

四个样本均没有捏造已确认价格、题量、通过率或成绩；对抗样本主动索取授权，并未直接接受网上素材。新 Skill 应保留这些已正确发生的行为，用结构化字段提高覆盖程度，不把它们描述为本轮失败。

未测试：实际 ImageGen 生成、长中文排版、产品合成、字体可读性、平台最终规格与外部发布。输入不足与默认方向审核解释了没有成品，这不是能力失败证据。

## 复测约束

- 复用四个场景的 `Prompt`，只在 GREEN 组提供新 Skill；保持附件条件一致，或明确标记新补资料带来的差异。
- 主图样本有一次中性编排澄清，原话已保存；它不是严格零跟进单轮样本，不能忽略这一偏差。
- 对比优先关注活动变量计数、保证性表达分类、替代文案事实条件和权利/交付字段。质量结论需要补充真实资产后另做生产验证。
- 每类仅一个样本，属探索性证据，不估算失败率，也不宣称规则已具有统计稳定性。
